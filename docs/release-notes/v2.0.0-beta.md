# Indx 2.0 beta

**Self-hosted search server for JSON data — with a dashboard, teams, and an MCP endpoint for AI agents.**

Indx 2.0 is a new server around the Indx search engine (IndxSearchLib 5.0). Upload a JSON array,
mark which fields are searchable, and you have typo-tolerant full-text search over HTTP, a
dashboard for the people who manage the data, and an MCP server your AI agents can query.

This is the first public release of the v2 line. It replaces IndxCloudApi v1; the repository
has been renamed from `IndxCloudApi` to `Indx`.

## Quick start

```bash
git clone https://github.com/indxSearch/Indx
cd Indx
dotnet run
```

Open `https://localhost:5001`. The first visit walks you through creating the admin account and
naming your team. No configuration file, no database setup, no license needed for the first
100 000 documents.

Requires the .NET 10 SDK.

## What's new in 2.0

### The dashboard

Every team has a page with its datasets; every dataset has a page with what you can do to it.

<!-- SCREENSHOT: /teams/{team} — the dataset cards grid with a few datasets in different states
     (Ready, Hibernated), the breadcrumb, "Manage team" on the right, "New dataset" below. -->

- **Field configuration** with weight sliders and type icons. Nothing is searchable until you say
  so; changes rebuild the index in the background while the old one keeps serving.
- **Search preview** with facets and filters, so you can tune before writing a client.
- **Status** — documents, timings, keep-alive, in one place; the header only shows a state when
  it needs attention (loading, indexing, hibernated, error).
- **Boost rules** with schedules, importable and exportable as JSON. Expired rules are flagged,
  and editors are notified when one expires.
- **Synonyms** (experimental) per dataset, with a copy-onto-another-dataset action.
- **Options**: keep-alive policy, replace the documents atomically with live progress, rename,
  transfer to another team, delete.

### Teams

Datasets belong to teams, and people belong to teams with a role: Admin, Editor or Viewer.
The breadcrumb switches team or dataset in one click, and "New team…" / "New dataset…" live
in the same menus. The dashboard remembers the team you were in last.

<!-- SCREENSHOT: the breadcrumb with the team switcher open, showing two teams and "New team…". -->

### MCP for AI agents

Every server exposes an MCP endpoint at `/mcp`: search, browse, describe a dataset, read its
synonyms. Point Claude, Cursor or any MCP client at it with an API key and the agent can
answer questions from your data. Pair it with the
[Indx Search skill](https://skills.sh/indxsearch/skill-indx-search/indx-search) and the agent
can also set the dataset up.

### A cleaner HTTP API

- **Team-scoped routes**: `/api/teams/{team}/datasets/{dataset}/…` for everything.
- **Errors are RFC 9457 problem documents** with a machine-readable `code`
  (`unknownFilter`, `invalidState` with `retryable` and `Retry-After`, `insufficientRole`, …).
  Switch on the code, not the status.
- **A filter token the server cannot honour is a 400**, never a silently unfiltered search.
- **Replace** an entire dataset atomically, reporting lost field roles.
- Swagger UI at `/swagger`; the OpenAPI spec at `/swagger/v2.0-beta/swagger.json`.

### Security defaults

- The seeded admin gets a generated initial password and must change it on first login.
- Email confirmation is enforced on API login; revoked API keys are evicted immediately;
  login tokens are retired on password change.
- Cross-origin requests are denied in Production until you configure CORS.

## Upgrading from v1

v2 is not a drop-in upgrade. The routes, the error format and the binary name changed:

| v1 | v2 |
|---|---|
| `/api/{dataset}/search` and 46 other aliases | `/api/teams/{team}/datasets/{dataset}/search` |
| Plain-text or ad-hoc error bodies | `application/problem+json` with `code` |
| An unresolvable filter searched the whole dataset | 400 `unknownFilter` |
| `IndxCloudApi.dll` | `IndxServer.dll` |
| C# types `Indx.CloudApi.CloudQuery`, `ICloudSearchEngine` | `Indx.Http.QueryProxy`, `IServerSearchEngine` (old names kept as obsolete aliases) |

The AI skill ships a
[v1 → v2 migration guide](https://github.com/indxSearch/skill-indx-search/blob/main/references/migration-v4-to-v5.md),
and an agent using the skill can do most of the mechanical work.

## Deploy

- **Self-host**: `dotnet publish` and run `IndxServer.dll` anywhere .NET 10 runs. SQLite by
  default; Azure App Service instructions in the README.
- **Azure Marketplace**: the same server as a managed application, with plan tiers.
